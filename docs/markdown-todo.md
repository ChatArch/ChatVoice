# Markdown Todo

把值得推进的想法变成行动计划，而不是让每段摘要都自动变成任务。

## 从摘要开始

1. 生成或完善会议摘要。
2. 在摘要下方点击 **转为 Todo**。
3. 页面切到独立的 **Todo** 标签，将当前摘要提炼为 Markdown 行动计划。原摘要和转写不变。

Todo 页初始为空是正常状态。打开标签或更新摘要不会自动生成任务。已有 Todo 再次生成时会确认替换，原版本可在当前页面撤销。

## 继续完善

左侧直接编辑 Markdown；右侧描述修改要求，或使用“拆成小步骤”“整理执行顺序”“补充完成标准”。模型依据摘要、当前 Todo 和本页的对话修改正文。取消、请求失败或编辑期间收到的过期结果不会覆盖当前正文。

使用标准任务语法记录进度：

```markdown
# 发布前检查

## 准备
- [x] 确认本次范围
- [ ] 整理测试报告
  - [ ] 汇总失败用例
  - [ ] 记录复现步骤

## 待确认
- [ ] 确认评审时间
```

**复制 Markdown** 和 **导出 .md** 保留普通文本格式，可交给其他 Markdown 工具继续处理。当前版本不提供思维导图，也不会自动执行待办或创建外部任务。

## 保存与隐私

- Todo 正文和本页完善对话随对应会议保存。账号模式使用原会议数据库；访客模式仅存于当前浏览器。
- 转换和完善会将本次摘要/Todo/相关对话发送给现有会议摘要模型，不需要额外模型配置。
- 旧会议默认空 Todo；清空会议会清空相应 Todo，切换会议不会混入上一条内容。
- AI 行动计划是建议，负责人、时间和完成标准仍应由使用者确认。

## API

- `POST /api/meeting-notes/todo`：`{"summary":"..."}` → `{"content":"Markdown", "model":"..."}`。
- `POST /api/meeting-notes/todo/revise`：`summary`、`current_todo`、`instruction`、可选 `messages` → 完整 Markdown `content`、简短 `reply`、`model`。
- 会议正文新增 `todo_markdown` 和 `todo_chat_messages`，同样出现在有权限的会议详情/数据导出。旧客户端省略这两个字段时不清空已保存 Todo。
